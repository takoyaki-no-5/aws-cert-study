## 順序の考え方

目的: 全冠を6か月で。**一度覚えた内容の再学習を最小化**する。

よく聞く **CLF → SAA → SAP** は正しい（SAA ⊂ SAP）。全冠でもこの軸は崩さない。Pro の直前には、その Pro に内容が近い非 Pro を置く。

| 連続ブロック | 順 | 理由（内容の近さ） |
|--------------|-----|-------------------|
| アーキ軸 | CLF → SAA → SCS → SAP → ANS | CLF⊂SAA⊂SAP。SCS は SAA/SAP のセキュリティと近い。ANS は SAP ネットワークの深化 |
| DevOps軸 | DVA → SOA → DOP | DOP は DVA+SOA の合成。アーキ軸の後にまとめて続ける |
| データ→AI軸 | DEA → AIF → MLA → AIP | DEA は分析寄り。AIF⊂MLA⊂AIP。コア/DevOps とほぼ非重複なので最後に一塊 |

**全体順:** CLF → SAA → SCS → SAP → ANS → DVA → SOA → DOP → DEA → AIF → MLA → AIP

やってはいけない: 非重複を軸の途中に挟む。

注: SCS（週25h）が回らなければ **SAA→DVA→SCS→SAP** に逃げてよい（受験日の組み替えが必要。ユーザー決定）。

## フェーズの型（週数に合わせて伸縮）

工数は上表。内訳の目安だけ示す（週数で倍々にしない）。

| フェーズ | 目安 |
|----------|------|
| 立ち上げ | 1.5〜2h |
| インプット | 必要工数の 35〜45%（最重量ドメインに厚く） |
