# 今日の予定 / 進捗 → Discord

固定タスク（どちらも **ユーザーが伝えたタイミング** で動かす。勝手に定期送信しない）:

1. **予定**: 今日の予定を出す →（必要なら調整）→ Discord
2. **進捗**: どこまでやったかを受け取る → day/log 更新 → Discord

## 前提

- 1日の学習枠（`study/profile.md` を正）:
  - **帰宅後 2時間40分（160分）** … テキスト中心
  - **電車 Anki 30分** … 帰宅後の**外**（別枠）
  - 当日だけ短縮（例: 2時間）ならユーザー指定を優先し day に明記
- Webhook: Cloud Secret / env **`discord_daily_bot`**
- 送信: `python3 .cursor/hooks/discord-notify.py`（URL をログに出さない）
- Anki: 電車が主。帰宅後はテキスト全部のあと（最後）に短く可

---

## A. 予定（開始時）

1. 読む: `study/profile.md` / `study/schedule.md` → 進行中 `study/<資格>/schedule.md` / 今日の `days/YYYY-MM-DD.md` / 直近 `study/log/` / 必要なら `books.md`
2. 今日の day が無ければ、未消化・roadmap・残り日数から **帰宅後160分＋電車30** に収まる案を作る（まだ確定・送信しない）。足りない分は無理に詰め込まず schedule の「不足」へ
3. **ズレ検知**（どれか当てはまったら、勝手に押し込めず **先に質問**）:
   - 前日以前の未完が残っている
   - 残り工数 ≫ 残り日数 × 190分
   - day の合計が枠を大きく超える／足りない
   - 受験日・リスケ判定日が近いのに進捗が薄い
4. チャットに短く提示（資格・日付・ブロック表・帰宅後分/電車分・次に始める1手）
5. ユーザーが OK / 無言で進めてよい流れなら Discord 送信。調整指示があれば「調整」へ

### 予定メッセージ

```
📅 YYYY-MM-DD（曜日） <資格略称>
帰宅後: NN分 / 160分（当日指定があればそちら）
電車 Anki: 30分

1. HH:MM〜 題材（分）
2. …
電車: Anki …

いまやること: …
```

---

## B. 進捗（ユーザーが伝えたとき）

トリガー例:「第3章終わった」「ここまでやった」「進捗送って」「今日ここまで」「切り上げ」「電車 Anki 済」

1. ユーザーの報告 + 今日の `days/` を照合して **済 / 未 / 次** を短くまとめる
2. day のチェックと `study/log/YYYY-MM-DD.md` を更新（曖昧なら確認してから）
3. Discord に進捗を送る（予定の再送と混ぜない。進捗用フォーマット）
4. チャットにも同じ要約を一言

途中報告でも終了報告でも同じ。**言われるまで送らない**（ブロック完了を推測して自動通知しない）。

### 進捗メッセージ

```
📊 YYYY-MM-DD（曜日） <資格略称> 進捗

済:
- …

未:
- …

次: …
（切り上げなら「今日はここまで」）
```

不明点（どのブロックまでか・電車 Anki したか等）があれば **聞いてから** 更新・送信。

---

## 送信

```bash
python3 .cursor/hooks/discord-notify.py "$(cat <<'EOF'
📅 ...
EOF
)"
```

成功後「Discord 送信済み」。失敗時は env / ネットワークを疑い、内容はチャットに残す。

## 調整（「これもやる」「これはやらない」）

ユーザー指示を day / 予定に反映してから、必要なら Discord を**再送**（訂正と分かる一文を先頭に）。

| 指示 | 動き |
|------|------|
| やらない・スキップ | そのブロックを外す。空いた分を次の優先題材に振るか、不足に回すか聞く |
| これもやる・追加 | **想定時間が分かる** → 帰宅後160＋電車30に収まる案を出して確認。**分からない** → **分数を聞いてから** day 更新・送信・学習開始しない |
| 順番変更 | 枠と「テキスト→Anki最後」を崩さない範囲で並べ替え |

### 質問してから動く（必須）

次は **推測で確定しない。質問 → 返答待ち**:

- 追加タスクの所要時間が不明
- 追加すると 160分超え／後続日にズレ込みそう
- 削ると合格リスクが変わりそう
- 進捗の範囲が曖昧（どこまで済か不明）
- リスケ判定や受験日に影響しそう

聞いてよい例:「追加分は何分想定？」「帰宅後160分超えるので A を明日？不足に書く？」「第9章の章末まで済？」

## ファイル更新

- 確定した予定 → `study/<資格>/days/YYYY-MM-DD.md`
- 進捗 → 同 day のチェック + `study/log/YYYY-MM-DD.md`
- 大きな配分変更 → 進行中 `schedule.md` の該当日

## やらない

- Webhook URL・シークレットをコミット・チャット全文に貼る
- 時間不明の追加を黙って押し込む
- ズレを黙って後日付に玉突きする
- 学習範囲を独断で削る
- 進捗を推測して勝手に Discord 送信する
